# Devil's advocate review: issue #10 (rerun)

## Earlier findings

1. Unverifiable fourth criterion: resolved, the criterion is deleted.
2. Price ties undefined: resolved, "products with the same price may appear in either order".
3. "Image" without pass condition: resolved, now "an image that loads".
4. Default order unstated: resolved, "When the list first opens, it is sorted by name, A to Z".

## Findings

1. **Two directions per checkbox** (#10 AC: "I can sort by name, A to Z and Z to A"; "...low to high and high to low; products with the same price..."). `docs/writing-tickets.md` asks for one checkbox per verifiable statement. If only Z to A breaks, the box is half true and the tie rule rides along. Fix: split into four criteria, one per direction, with the tie rule on its own line or on the price ones.

2. **"An image that loads" passes the wrong image** (#10 AC 1). A product showing another product's picture still loads, so that rendering defect meets the criterion. Fix: "an image that loads and shows that product".

3. **"First opens" has no boundary** (#10 AC 2). It is unclear whether this means each visit to the list or only the first per session; a test returning from a product page cannot tell which order to expect. Fix: say "each time the list is shown after sign-in", or state the scope.

## Also noticed

- #9 still says "reorders the list correctly" and keeps cart criteria with no story; already tracked in `docs/reviews/2026-09-03-issue-9-rerun.md`, so a reference.

## In its favour

The new default-order criterion gives every sort a known starting state, and the tie clause stops a spec from asserting an arbitrary sequence. I nearly objected to "six products" again; it still matches #9 and is gradable.

## Verdict

**Objections.** All four earlier findings are resolved. I tried to find harness bleeding, a prescribed implementation, a wrong phase and a broken chain (parent #9, `area:inventory`, Phase 2 all hold); none held. The remaining defects are bundled criteria and two loosely bounded phrases.
