# Review: Issue #9 — [REQ] Product inventory

## Findings

1. **Context contradicts its own criteria, and the chain breaks at #10.**
   Context: "the cart and the checkout are covered separately," yet three of
   six criteria ("Adding an item updates its button... increments the cart
   badge," "Removing an item reverses both," "cart badge is empty") are cart
   behavior. Child story #10 covers only browse/sort — none of its criteria
   trace to those three. Consequence: a test case written against them has
   no story ancestor, breaking the requirement→story→test-case chain
   `docs/traceability.md` records. Fix: delete the three cart criteria from
   #9 (or move them under a cart requirement/story) so Context and criteria
   agree.

2. **Area mismatch with the cart criteria.** Area is set to `inventory`
   (single-select per `requirement.yml`), but `docs/plan.md`'s label table
   treats cart as its own area (`area:cart`, `src/pages/CartPage.ts`,
   `tests/e2e/cart/`). Consequence: cart-badge criteria filed under
   `area:inventory` misroute future defects and dashboards for that area.
   Fix: same as above — remove the cart criteria rather than relabel.

3. **"Correctly" has no fixed meaning.** "Sorting by name... reorders the
   list correctly" and "by price... correctly" don't say what correct order
   is (case sensitivity, locale rules, numeric vs string price compare).
   Consequence: two test-case authors could each write a different expected
   result and both call it coverage of the same criterion. Fix: state the
   expected order directly, e.g. "list matches ascending name order,
   case-insensitive."

## In its favour

"All six products render, each with a name, description, price and image"
is a single, countable, pass/fail statement — a test case can assert exactly
four fields on exactly six cards with no interpretation needed. That
precision is what the vaguer sort criteria (Finding 3) fail to reach.

## Verdict: objections

I tried to break the requirement↔story parent link and the area/template
fields — both hold: #10 correctly names `#9` as its parent requirement, and
the area dropdown value is valid. The objections are about scope leaking
across a stated boundary, not about missing links or malformed fields.
